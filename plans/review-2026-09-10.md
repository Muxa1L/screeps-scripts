## P0 — Critical (release-blocking)

### P0-1 — `creepsBodies.js`: duplicate `const SCOUT_BODIES` → whole module fails to load

- **Where:** `src/economy/creepsBodies.js:86` **and** `:124`
- **What:** `SCOUT_BODIES` is declared twice in the same module scope. In a standalone
  file this is a hard `SyntaxError`. The build bundler wraps (not parses) modules, so it
  copies **both** declarations into `dist/main.js`.
- **Evidence:**
  - `node --check src/economy/creepsBodies.js` → `SyntaxError: Identifier 'SCOUT_BODIES' has already been declared`
  - `node --check dist/main.js` → same error (at dist lines 366 and 404)
  - `require('./src/economy/creepsBodies.js')` throws
  - Cascade: `creepManager`, `spawnManager`, `creepRunner` all fail to load →
    `assert.safeTickTimed` swallows the throw **every tick** → creeps don't move and
    nothing spawns (total economy/defense shutdown), leaving only error counters in
    `Memory.stats`.
  - Failing test files (all load-time failures): `creepsBodies.test.js`,
    `creepManager.test.js`, `creepRunner.test.js`, `spawnManager.test.js`.
- **Impact:** On the live shard the module fails to evaluate → **the AI does nothing.**
  This is the worst possible state and is the first thing to fix.
- **Fix:** delete the second declaration (keep line 86, which carries the explanatory
  comment). Remove `src/economy/creepsBodies.js:124-126`:
  ```js
  const SCOUT_BODIES = {
      50: [MOVE],
  };
  ```
  and collapse the resulting double blank line before `RESERVER_BODIES`.
- **Verify:**
  - `node --check src/economy/creepsBodies.js` → clean
  - `npm test` → the 4 cascading files pass
  - `npm run build && node --check dist/main.js` → clean

## P1 — High (feature breakage, already surfaced by tests)

### P1-2 — `expansionPlanner.js`: wrong `require` path for `cartographer`

- **Where:** `src/managers/expansionPlanner.js:33` and `:46`
- **What:** `require('../../services/cartographer')` resolves to `<root>/services/cartographer`
  (does not exist). The module lives at `src/services/cartographer.js`; from
  `src/managers/` the correct relative path is `../services/cartographer`.
  - (Compare `src/managers/upkeep/intelService.js:10`, which **correctly** uses
    `../../services/cartographer` because it sits one level deeper in `upkeep/`.)
- **Evidence:** `expansionPlanner.test.js → findCandidates returns neighbors of owned rooms`
  fails with `Cannot find module '../../services/cartographer'`. At runtime
  `isOwnedByOther` / `isReservedByNonAlly` throw the same → expansion scoring breaks.
- **Fix:** change both lines to `require('../services/cartographer')`.
- **Verify:** `npm test` expansionPlanner passes; `isOwnedByOther`/`isReservedByNonAlly` no longer throw.

### P1-3 — `creepRunner.js`: `room` not in scope inside `combatIdleFallback`

- **Where:** `src/managers/creepRunner.js:555, 556, 559, 562` (all four flagged `no-undef`)
- **What:** `combatIdleFallback(creep)` references `room.name` in the "parked at spawn"
  branch, but `room` is neither a parameter nor a local. It is called from
  `runIdleFallback(creep, room)` at `:622` for `fighter`/`healer` roles.
- **Evidence:** `npx eslint src/` → 4× `'room' is not defined`. Runtime: a fighter/healer
  with no hostiles standing near a spawn throws `ReferenceError: room is not defined`
  (caught per-creep, so that creep freezes until the next re-evaluation).
- **Fix:** thread `room` through — change the signature to
  `combatIdleFallback(creep, room)` and the single call site (`:622`) to
  `combatIdleFallback(creep, room)`. (The export at `:870` is just the function
  reference and needs no change.)
- **Verify:** `npx eslint src/` → no `no-undef`; combat idle-parking path runs cleanly.

## Regression prevention (why these slipped)

- **Build doesn't parse.** `scripts/build.js` wraps modules without a syntax check, so a
  `SyntaxError` in one source file silently produced an unparseable `dist/main.js` and the
  build still "succeeded." Add `node --check dist/main.js` to `scripts/build.js` (fail the
  build on syntax error) and/or a CI step.
- **Lazy `require` masks load failures.** `main.js` requires managers inside `loop()`, and
  `assert.safeTickTimed` swallows the throw, so a broken module looks like a per-tick error
  log rather than a startup crash. Add a smoke test that `require()`s `dist/main.js` (or
  each `src/` entry point) so a load-time `SyntaxError` is caught in CI, not on the shard.
- **Refactor left stale tests.** `intelService` was rewritten to proxy `cartographer` but
  its test file still targets the old API. Keep the test file in the same PR as the refactor.
- **Throwaway scripts committed.** Diagnostic scripts were committed and are now lint
  targets. Keep them out of the repo (gitignore) or name them `.mjs`.
