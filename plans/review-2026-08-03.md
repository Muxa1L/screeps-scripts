## Critical Bugs

### N1 — nukeService: `nukesDetected` inflated every tick while nuke is in flight
**File:** `src/managers/upkeep/nukeService.js:41`  
**Severity:** CRITICAL

Counter incremented inside the per-nuke loop, which runs every tick the nuke
is visible in `FIND_NUKES`. A nuke with `timeToLand = 5000` inflates the
counter by 5000.

**Fix:** Only increment on first detection, e.g. gate on
`if (!nuke.events[rn + ':' + n.id]) nuke.stat.nukesDetected++;`

### N2 — nukeService: `events[rn]` overwritten on multi-nuke rooms
**File:** `src/managers/upkeep/nukeService.js:34`  
**Severity:** CRITICAL

Keyed by room name only. With 2+ nukes on the same room in the same tick,
only the last nuke's `pos`, `timeToLand`, `launchRoomName`, and
`safeModeActivated` survive. Earlier nuke's data is lost.

**Fix:** Key by `rn + ':' + n.id` (nuke objects have stable `id`).

### N3 — nukeService: `events[rn].detectedTick` reset every tick
**File:** `src/managers/upkeep/nukeService.js:35`  
**Severity:** CRITICAL

The event object is recreated each tick, so `detectedTick` is always
`Game.time`. The `NUKE_EVENT_TTL` cleanup never fires for active nukes, and
stale events linger in `Memory.nuke.events` for any room that ever had a nuke.

**Fix:** Only set `events[rn+':'+n.id]` once per nuke (gate on existence).

## High Bugs

### N4 — memorySchema: `getSourceMemory` returns transient object never written back
**File:** `src/utils/memorySchema.js:188-199`  
**Severity:** HIGH

When the entry is missing, a fresh default object is returned without
`Memory.sources[id] = {...}`. Any caller that mutates the returned object
(e.g. `mem.slots.push(...)`) loses the change. Also allocates a fresh object
on every call → GC pressure. Compare with correct `getRoomMemory` pattern.

**Fix:**
```js
if (!Memory.sources[id]) Memory.sources[id] = { roomName: '', x: 0, y: 0, slots: [] };
return Memory.sources[id];
```

### N5 — watchdogService: false positive when `_diedAt` is unset or `0`
**File:** `src/managers/upkeep/watchdogService.js:11`  
**Severity:** HIGH

`const diedAt = Memory.creeps[cname]._diedAt || 0;` coerces missing `_diedAt`
to `0`, making `age = Game.time - 0` huge. Triggers `GHOST_CRITICAL_AGE` (15)
every tick for any dead creep whose `_diedAt` hasn't been stamped yet (if
watchdog runs before `memoryCleanupService`). Also masks a genuine
`_diedAt === 0`.

**Fix:**
```js
const diedAt = Memory.creeps[cname]._diedAt;
if (diedAt === undefined) continue;
const age = Game.time - diedAt;
```

### N6 — stuckRecycleService: fresh creeps immediately flagged stuck
**File:** `src/managers/upkeep/stuckRecycleService.js:46`  
**Severity:** HIGH

`getLastTaskChange` returns `0` when unset, so
`Game.time - 0 > STUCK_THRESHOLD` (200) is always true on the very first tick
of a newly-spawned creep (before `setLastTaskChange` runs). The creep is
logged as "idle for X ticks" and queued for recycling.

**Fix:** Skip creeps with `memory.getLastTaskChange(c) === 0`, or default the
field in `ensureCreepMemory`.

## Medium Bugs

### N7 — safeModeService: cooling-block log spam
**File:** `src/managers/upkeep/safeModeService.js:37-51`  
**Severity:** MEDIUM

`_safeModeCooldownLogged` is only cleared on successful activation (line 59).
But `controller.safeModeCooldown` is a long-lived native property (~20 000
ticks after activation). So a room in the long native cooldown window keeps
logging "blocked by cooldown=…" every tick the attack conditions hold.

**Fix:** Also skip logging while `controller.safeModeCooldown` is truthy and
`_safeModeCooldownLogged` already shows the same reason.

### N8 — constructionPlanner: `planRoom` doesn't guard `room.controller`
**File:** `src/planning/constructionPlanner.js:26`  
**Severity:** MEDIUM

`const limits = STRUCTURE_LIMITS[room.controller.level];` throws if
`room.controller` is `undefined`. `tick()` guards on
`room.controller && room.controller.my`, but `planRoom` is exported and could
be invoked directly with a non-controller room (highway, SK room).

**Fix:** `if (!room.controller) return;` before the limits lookup.

### N9 — intelService: `intel._pendingScans` can leak for never-visible rooms
**File:** `src/managers/upkeep/intelService.js:160-172`  
**Severity:** MEDIUM

A scanned room that never becomes visible (invalid name, out of observer
range, permanently blocked) stays in `_pendingScans` forever; the filter only
removes entries where `Game.rooms[roomName]` becomes truthy. Cross-tick dedup
also blocks re-pushing the same room, so it never naturally clears.

**Fix:** Add a TTL on `_pendingScans` entries (e.g. drop after
`INTEL_QUEUE_REFRESH_TICKS` ticks).

### N10 — taskReserve: level-0 controller (reserved by enemy) infinite retry
**File:** `src/tasks/types/taskReserve.js:89`  
**Severity:** MEDIUM

```js
if (res === ERR_INVALID_TARGET && controller.level > 0) {
    entry.status = 'contested';
    return false;
}
```

When `reserveController` returns `ERR_INVALID_TARGET` and `controller.level === 0`
(controller reserved by another player but not yet claimed), the function falls
through to `return true`. The creep keeps trying to reserve every tick. Each
tick the reserve action has a cooldown, so it does nothing. The creep sits
there.

**Fix:** Remove the `controller.level > 0` guard, or handle the level-0 case.

## Observations (not bugs)

### `getLastTaskChange` cache miss perf
`taskBase.pathScore` cache key includes `creep.pos.x,creep.pos.y`. A moving
creep invalidates the cache on every tick. The cache is only useful when the
creep is stationary. Cap of `PATH_SCORE_MAX_ENTRIES` is a backstop.
(Performance, not correctness.)

### Hardcoded threshold in taskHaul.tasks
`src/tasks/types/taskHaul.js:26` — `if (c.store[RESOURCE_ENERGY] >= 100)` uses
hardcoded `100`; should use `constants.CONTAINER_WITHDRAW_MIN` for consistency.

### taskRemoteDefend idle at home
When at home and bucket low, task is kept (creep sits idle) instead of released.
Releasing would let the scheduler re-evaluate for other work.

### taskClaim controller.my race
`controller.my` is set by the engine on the next tick after `claimController`
returns OK. Causes 1-tick delay in success branch. Minor.

### taskReserve reservationExpires set to Game.time
When `res === OK` but `controller.reservation` is briefly undefined (just-claimed),
`reservationExpires = Game.time + 0 = Game.time`. Cosmetic — entry is set
same tick and remoteManager refreshes next tick.
